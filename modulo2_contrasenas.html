01 / EN 1 MINUTO

Lo esencial

  1. Las contraseñas nunca se guardan en texto plano. Si roban la base, el atacante tiene todas las cuentas.
  2. Codificar (Base64) lo revierte cualquiera. Cifrar (AES) se revierte con la clave. El hash no se revierte: es lo que corresponde para contraseñas.
  3. La sal (valor al azar por usuario) hace que dos claves iguales den hashes distintos. El costo hace el hash lento a propósito: bcrypt costo 12 tarda unos 0,23 s por intento; MD5, millonésimas.
  4. password_hash($clave, PASSWORD_BCRYPT, ['cost' => 12]) genera la sal sola y la guarda dentro del hash ($2y$12$..., 60 caracteres).
  5. Para verificar se usa password_verify($clave, $hash). Nunca se compara con === contra un hash nuevo.
  6. Límites: el hash no evita que roben la base, solo reduce el daño; una clave débil igual se adivina; bcrypt solo usa los primeros 72 bytes.
  7. Lo que se demostró: con la base filtrada, la vulnerable dejó entrar con las claves leídas; en la protegida, el hash pegado como contraseña fue rechazado.
02 / TEORÍA

Conceptos

1. Por qué no se guarda la contraseña tal cual

Guardar en texto plano es guardar la contraseña exactamente como se escribió. Si alguien copia la base (un respaldo, phpMyAdmin, una inyección SQL), lee todas las claves y entra con cualquier cuenta. Pasó de verdad: en 2009 la empresa RockYou expuso más de 32 millones de cuentas guardadas en texto plano.

ComparaciónEs como guardar las llaves de todos los consultorios colgadas con una etiqueta que dice de quién es cada una. Al que entra a la oficina le alcanza con agarrarlas.

2. Codificación, cifrado y hash

Son tres cosas distintas. Solo el hash sirve para contraseñas, porque es de un solo sentido: del resultado no se vuelve al original.

Técnica¿Se revierte?Ejemplo¿Para contraseñas?
CodificaciónSí, cualquieraBase64: hola1234 → aG9sYTEyMzQ=No
CifradoSí, con la claveAESNo (si se filtra la clave, salen todas)
HashNobcrypt, Argon2idSí, con sal y costo alto

Para recordar: codificar = otra forma de escribir; cifrar = candado con llave; hash = picadora de carne (no se vuelve atrás).

3. La sal

La sal es un valor al azar, distinto para cada usuario, que se mezcla con la contraseña antes de hacer el hash. Así, dos personas con la misma clave tienen hashes distintos. Además no sirven las tablas precalculadas (listas ya armadas de “clave → hash”).

password_hash("hola123", PASSWORD_BCRYPT, ['cost' => 12]);  // $2y$12$Xk3...
password_hash("hola123", PASSWORD_BCRYPT, ['cost' => 12]);  // $2y$12$pQ9...  (otro distinto)

4. El costo: un hash lento a propósito

El costo (factor de trabajo) hace que cada hash tarde más en calcularse. Al usuario no le molesta esperar 0,23 s una vez, pero el atacante que prueba millones de claves se frena. Por eso MD5 o SHA-1 no sirven para contraseñas: son rápidos. OWASP recomienda Argon2id, scrypt o bcrypt.

Medición del grupoTexto plano: ~28 millones de intentos por segundo. MD5: ~6 millones. bcrypt costo 12: ~4.

5. password_hash()

Es la función de PHP para guardar contraseñas. Genera la sal sola y devuelve un texto que trae todo junto: algoritmo, costo, sal y hash. Con bcrypt siempre mide 60 caracteres, por eso la columna de la contraseña tiene que ser VARCHAR(255) (el tamaño que recomienda el manual de PHP).

$claveHash = password_hash($clave, PASSWORD_BCRYPT, ['cost' => 12]);
// $2y$12$ + 22 caracteres de sal + 31 de hash
//  2y = bcrypt   12 = costo

6. password_verify() y password_needs_rehash()

password_verify() saca del hash guardado el algoritmo, el costo y la sal, calcula el hash de lo que se escribió y compara: devuelve true o false. Por eso pegar el hash robado como contraseña no sirve: el sistema hace el hash de ese texto y no coincide. password_needs_rehash() avisa si el hash guardado tiene un costo o algoritmo viejo, para recalcularlo cuando el usuario entra.

if (password_verify($clave, $fila['usu_clave'])) {      // true: clave correcta
    if (password_needs_rehash($fila['usu_clave'], PASSWORD_BCRYPT, ['cost' => 12])) {
        // calcular el hash nuevo y guardarlo
    }
}

05 / CÓDIGO

El código explicado

Las dos versiones solo se diferencian en dos lugares. Los fragmentos son los del informe.

1. Al guardar la contraseña: php/usuarios.php

Vulnerable 
// se guarda tal cual
$claveGuardada = $clave;

En la base queda la clave tal cual, legible.

Protegido 
// se guarda solo el hash bcrypt
$claveHash = password_hash($clave, PASSWORD_BCRYPT, ['cost' => 12]);

En la base queda $2y$12$... (60 caracteres).

2. Al iniciar sesión: php/acceso.php

Vulnerable 
// compara texto con texto
} elseif ($clave === $fila['usu_clave']) {

Solo funciona si la base tiene la clave legible.

Protegido 
// recalcula el hash y compara
} elseif (password_verify($clave, $fila['usu_clave'])) {
    if (password_needs_rehash($fila['usu_clave'], PASSWORD_BCRYPT, ['cost' => 12])) {
        // se vuelve a calcular el hash con el costo actual
    }

Calcula el hash de lo escrito con la sal guardada y compara.

06 / ESCENARIOS

Ejemplos paso a paso

1. Se filtra la tabla usuarios (P1)

Acción: el atacante consigue una copia de la tabla y mira la columna usu_clave.

Vulnerable

Lee las 3 contraseñas. Ya puede entrar con cualquiera.

Protegido

Ve 3 hashes de 60 caracteres que empiezan con $2y$12$. No lee ninguna clave.

2. Dos usuarios con la misma contraseña (P1)

Acción: carlos y laura tienen la misma clave.

Vulnerable

En la tabla aparece el mismo valor dos veces: se nota que la comparten.

Protegido

Cada uno tiene su sal: los dos hashes son distintos y no se nota nada.

3. Pegar el valor filtrado como contraseña (P5)

Acción: el atacante copia el valor de usu_clave de laura y lo escribe en el login.

Vulnerable

El valor es la contraseña real: entra. El registro de intentos lo anota como exitoso.

Protegido

password_verify calcula el hash del hash pegado, que no coincide: “clave incorrecta”. Queda como intento fallido.

4. Alta de un usuario nuevo (P4)

Acción: el administrador crea un usuario nuevo con su clave.

Vulnerable

En la base queda la clave tal cual.

Protegido

En la base queda un hash bcrypt.

5. El atacante prueba un diccionario fuera de línea (P8)

Acción: con la tabla robada, prueba un millón de contraseñas comunes en su computadora.

Vulnerable

No necesita adivinar: ya tiene las claves.

Protegido

A 0,23 s por intento, un millón de pruebas contra un solo hash tarda unos 2,7 días.

6. Uso normal (P2, P3 y P6)

Acción: un usuario entra con su clave, después prueba una clave incorrecta y cierra sesión.

Vulnerable

Entra, rechaza la clave mala y vuelve al login.

Protegido

Igual. La protección no cambia nada para el usuario legítimo.

Qué se demostró

  • Con la base filtrada, la vulnerable entregó las 3 contraseñas y dejó entrar con ellas; la protegida solo mostró hashes que no sirvieron para entrar.
  • El uso normal (entrar, rechazar la clave mala, cerrar sesión) funcionó igual en las dos.
  • Para el usuario, 0,23 s al entrar no se nota; para el atacante, es un freno enorme.
Limitaciones que reconoce el grupo: el hash no impide que roben la base, solo reduce el daño. Una clave débil (por ejemplo, un nombre seguido de 123) igual se puede adivinar con tiempo. Los tiempos dependen de la computadora. OWASP hoy prefiere Argon2id y deja bcrypt cuando Argon2id no está disponible, y bcrypt solo usa los primeros 72 bytes de la contraseña.

09 / REPASO

Preguntas probables

Tocá cada pregunta para ver la respuesta.

¿Por qué no se guardan las contraseñas en texto plano?

Porque si se filtra la base, el atacante tiene todas las claves y entra con cualquier cuenta.

¿Qué diferencia hay entre codificación, cifrado y hash?

La codificación la revierte cualquiera; el cifrado se revierte con la clave; el hash no se revierte.

¿Qué es la sal y para qué sirve?

Un valor al azar distinto por usuario. Hace que claves iguales den hashes distintos y que no sirvan las tablas precalculadas.

¿Qué es el costo de bcrypt?

El factor que hace lento el cálculo. Cada punto duplica el tiempo; el grupo usó 12 (~0,23 s).

¿Por qué no usar MD5?

Porque es rápido: permite millones de intentos por segundo.

¿Qué devuelve password_hash()?

Un texto con algoritmo, costo, sal y hash juntos. Con bcrypt empieza con $2y$ y mide 60 caracteres.

¿Cómo se verifica la contraseña al iniciar sesión?

Con password_verify($clave, $hashGuardado), que devuelve true o false.

¿Qué hace password_needs_rehash()?

Avisa si el hash guardado usa otro algoritmo o costo, para recalcularlo cuando el usuario entra.

¿Por qué no sirve pegar el hash robado como contraseña?

Porque el sistema hace el hash de lo escrito; el hash de un hash no coincide con el guardado.

¿Qué se demostró en P1 y P5?

P1: en la vulnerable se leen las claves; en la protegida, solo hashes distintos. P5: con el valor filtrado se entra en la vulnerable y se rechaza en la protegida.

¿Qué algoritmos recomienda OWASP?

Argon2id en primer lugar; scrypt o bcrypt si no está disponible.
