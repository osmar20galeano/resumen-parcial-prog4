Fuerza bruta

Qué pasa cuando un login deja probar contraseñas sin límite, y cómo se frena con contadores, bloqueos, límite por IP y un registro de intentos.

01 / EN 1 MINUTO

Lo esencial

  1. Fuerza bruta: probar contraseñas una tras otra, de forma automática, hasta acertar. Funciona si el login no pone límite.
  2. La versión vulnerable de Banco Alfa: intentos ilimitados, sin bloqueo y contraseñas en texto plano.
  3. Bloqueo escalonado por usuario: 3 fallos → 2 minutos bloqueado; 3 fallos más → bloqueo permanente, que solo libera Soporte.
  4. Límite por IP: más de 10 fallos en 15 minutos desde la misma dirección → respuesta 429 (demasiadas peticiones).
  5. Mensaje único y tiempo parejo: el atacante no puede saber si un usuario existe.
  6. Login correcto → contadores en cero. Cada intento queda registrado.
  7. La contra: un atacante puede bloquear a propósito la cuenta de otro, y el límite por IP puede afectar a toda una oficina.
02 / TEORÍA

Conceptos

1. Qué es un ataque de fuerza bruta

Es probar muchas contraseñas, con un programa, hasta que una funcione. Si el login no limita los intentos, tarde o temprano acierta. Hay dos variantes:

  • Diccionario: en lugar de probar todo, prueba una lista de contraseñas comunes (123456, password…).
  • Password spraying: prueba una sola contraseña común contra muchos usuarios, para no disparar el bloqueo de ninguno.
ComparaciónEs como un candado de bicicleta de 3 números: si nadie te detiene, probás 000, 001, 002… y en algún momento abre.

2. Contador por usuario y bloqueo escalonado

El sistema cuenta los fallos de cada usuario. Al tercer fallo bloquea la cuenta 2 minutos (bloqueo temporal). Si vuelve a fallar 3 veces, el bloqueo es permanente y solo lo quita el personal de Soporte.

Estado de la cuentaCómo llegaCómo sale
Normal——
Bloqueo de 2 minutos3 fallos seguidosPasan los 2 minutos, o Soporte la libera
Bloqueo permanente3 fallos más después del bloqueo temporalSolo Soporte la libera

Un login correcto pone todos los contadores en cero.

3. Límite por IP

La IP es la dirección de la máquina que hace el pedido. Si desde la misma IP hay más de 10 fallos en 15 minutos, el sistema responde 429 y no deja seguir. Sirve contra el password spraying, que cambia de usuario pero no de máquina.

if ($fallosIp >= 10) {
    http_response_code(429);   // demasiadas peticiones
    exit;
}

4. Mensaje único y tiempo parejo

Si el login dice “el usuario no existe”, el atacante aprende qué usuarios son reales (enumeración de usuarios). Por eso hay un solo mensaje para todo: “Usuario o contraseña incorrectos”. Además, el sistema tarda lo mismo exista o no el usuario: si no existe, igual verifica un hash falso.

SituaciónSi “usuario inexistente” responde en 1 ms y “clave incorrecta” en 230 ms, el atacante descubre los usuarios mirando el reloj, aunque el mensaje sea el mismo.

5. Contador en un solo UPDATE y fechas en MySQL

Si PHP lee el contador, le suma 1 y lo guarda, dos intentos al mismo tiempo pueden leer el mismo número y perder un fallo (condición de carrera). Haciendo la suma dentro de un solo UPDATE, MySQL la hace de una vez. Las fechas del bloqueo también las calcula MySQL con NOW() (ahora) y DATE_ADD (sumar tiempo), así guardar y comparar usan el mismo reloj.

UPDATE usuarios SET asu_intentos = asu_intentos + 1 WHERE asu_nombre = ?;
-- bloqueado hasta: DATE_ADD(NOW(), INTERVAL 2 MINUTE)  →  ahora + 2 minutos

6. Reinicio del contador y registro de intentos

Cuando el login es correcto, los contadores vuelven a cero; así un usuario que se equivocó ayer no queda bloqueado hoy por un solo error. Además, cada intento se guarda en la tabla log_intentos (usuario, IP, resultado y fecha). Ese registro sirve para ver ataques y para contar los fallos por IP.

registrarIntento($con, $usuario, $ip, "fallido");

Códigos HTTP que aparecen

CódigoNombreCuándo lo usa Banco Alfa
401Unauthorized (no autorizado)Credenciales incorrectas o cuenta bloqueada (con el mensaje único).
405Method Not Allowed (método no permitido)Se pide acceso.php con GET en lugar de POST.
429Too Many Requests (demasiadas peticiones)Más de 10 fallos desde una IP en 15 minutos.
La contra del bloqueo: cualquiera puede escribir mal 6 veces la clave de otro usuario y dejarlo bloqueado (es una denegación de servicio). Y el límite por IP usa REMOTE_ADDR: en una oficina o red compartida, todos salen con la misma IP, así que los fallos de uno pueden dejar a todos con 429. El grupo sugiere evaluar CAPTCHA, retardos progresivos o avisos.

05 / CÓDIGO

El código explicado

Ojo: el informe no trae fragmentos de código. Todo el código de esta sección es ilustrativo: se armó a partir de lo que el informe describe (tablas, columnas, límites y códigos HTTP). Los nombres de columnas (asu_intentos, asu_bloqueos, asu_bloqueado_hasta) y de la función registrarIntento() sí son los del informe.

1. Verificar la contraseña: php/acceso.php

Vulnerable 
$sql = "SELECT * FROM usuarios
        WHERE asu_nombre = ? AND asu_clave = ?";
$stmt = $con->prepare($sql);
$stmt->bind_param("ss", $usuario, $clave);
$stmt->execute();
$fila = $stmt->get_result()->fetch_assoc();

registrarIntento($con, $usuario, $ip,
                 $fila ? "exitoso" : "fallido");
if ($fila) {
    $_SESSION["usuario"] = $fila["asu_nombre"];
    echo json_encode(["ok" => true]);
} else {
    echo json_encode(["ok" => false]);
}

Sin límite: se puede repetir para siempre. La clave está en texto plano. Usa consulta preparada, así que no tiene inyección SQL.

Protegido 
if ($_SERVER["REQUEST_METHOD"] !== "POST") {
    http_response_code(405);
    exit;
}
// 1) límite por IP
if (fallosDeIp($con, $ip) >= 10) {
    registrarIntento($con, $usuario, $ip, "bloqueado_ip");
    http_response_code(429);
    exit;
}
// 2) buscar al usuario (solo por nombre)
//    trae también: asu_bloqueado_hasta > NOW() AS bloqueada
$fila = buscarUsuario($con, $usuario);
// 3) tiempo parejo: siempre se verifica un hash
$hash = $fila ? $fila["asu_clave"] : $HASH_FALSO;
$claveOk = password_verify($clave, $hash) && $fila;
// 4) cuenta bloqueada: se rechaza aunque la clave sea buena
if ($fila && $fila["bloqueada"]) {
    registrarIntento($con, $usuario, $ip, "bloqueado");
    http_response_code(401);
    echo json_encode(["ok" => false,
        "mensaje" => "Usuario o contraseña incorrectos"]);
    exit;   // no suma fallos mientras dura el bloqueo
}

Primero los filtros (método, IP, bloqueo) y después la decisión.

2. Qué pasa después: fallo o acierto

Vulnerable 
// no hay contador ni bloqueo:
// el fallo solo se registra
registrarIntento($con, $usuario, $ip, "fallido");

El registro existe, pero nada actúa sobre él.

Protegido 
if (!$claveOk) {
    sumarFallo($con, $usuario);   // un solo UPDATE
    registrarIntento($con, $usuario, $ip, "fallido");
    http_response_code(401);
    echo json_encode(["ok" => false,
        "mensaje" => "Usuario o contraseña incorrectos"]);
    exit;
}
// login correcto
session_regenerate_id(true);
$sql = "UPDATE usuarios SET asu_intentos = 0, asu_bloqueos = 0,
        asu_bloqueado_hasta = NULL WHERE asu_nombre = ?";
registrarIntento($con, $usuario, $ip, "exitoso");

Mismo mensaje para todo; al acertar, contadores a cero.

3. El contador en un solo UPDATE

UPDATE usuarios SET
  -- se escribe primero: MySQL usa los valores ya cambiados en las columnas siguientes
  asu_bloqueado_hasta = IF(asu_intentos + 1 >= 3,
        IF(asu_bloqueos = 0, DATE_ADD(NOW(), INTERVAL 2 MINUTE), '9999-12-31'),
        asu_bloqueado_hasta),
  asu_bloqueos = IF(asu_intentos + 1 >= 3, asu_bloqueos + 1, asu_bloqueos),
  asu_intentos = IF(asu_intentos + 1 >= 3, 0, asu_intentos + 1)
WHERE asu_nombre = ?;

En palabras: suma un fallo. Si llega a 3, bloquea: la primera vez, 2 minutos (DATE_ADD(NOW(), INTERVAL 2 MINUTE)); la segunda, para siempre. Todo en una sola orden, sin que PHP lea y escriba por separado.

06 / ESCENARIOS

Ejemplos paso a paso

1. Un programa prueba 1000 claves contra “admin”

Acción: el atacante usa una lista de contraseñas y las manda una tras otra.

Vulnerable

Las 1000 se procesan. Si la clave está en la lista, entra.

Protegido

Al tercer fallo, la cuenta queda bloqueada 2 minutos. Las siguientes reciben el mismo mensaje y se rechazan, aunque alguna sea la correcta.

2. Sigue probando después del bloqueo temporal

Acción: espera los 2 minutos y falla 3 veces más.

Vulnerable

Nunca se bloquea.

Protegido

Bloqueo permanente. El dueño tiene que pedirle a Soporte que lo libere; Soporte queda registrado en log_soporte.

3. Password spraying desde una máquina

Acción: prueba 123456 con 50 usuarios distintos, 1 intento cada uno.

Vulnerable

Prueba los 50 sin problema.

Protegido

Ninguna cuenta llega a 3 fallos, pero la IP sí llega a 10: a partir de ahí responde 429.

4. Averiguar qué usuarios existen

Acción: prueba “juan” (no existe) y “maria” (existe) con una clave cualquiera.

Sin mensaje único

“Usuario no existe” para juan y “Clave incorrecta” para maria: ya sabe que maria es real.

Protegido

Los dos reciben “Usuario o contraseña incorrectos” y tardan lo mismo.

5. Un usuario legítimo se equivoca

Acción: falla 2 veces, a la tercera acierta. Al otro día se equivoca 1 vez.

Sin reinicio

Los 2 fallos viejos + el nuevo suman 3: queda bloqueado por un solo error.

Protegido

Al acertar, el contador volvió a 0. El error del otro día cuenta como 1.

6. La contra: bloquear a otro a propósito

Acción: alguien que conoce el usuario de un cliente escribe 6 claves falsas.

Vulnerable

No pasa nada (pero tampoco hay protección).

Protegido

El cliente queda bloqueado para siempre hasta que Soporte lo libere. Es una denegación de servicio que el propio informe reconoce.

09 / REPASO

Preguntas probables

Tocá cada pregunta para ver la respuesta.

¿Qué es un ataque de fuerza bruta?

Probar contraseñas de forma automática hasta acertar, aprovechando que el login no limita los intentos.

¿Qué diferencia hay con diccionario y password spraying?

Diccionario prueba una lista de claves comunes; spraying prueba una clave contra muchos usuarios.

¿Qué fallaba en la versión vulnerable?

Intentos ilimitados, sin bloqueo, clave en texto plano y sin regenerar el ID de sesión.

¿Cómo es el bloqueo escalonado?

3 fallos → 2 minutos; 3 fallos más → permanente; Soporte desbloquea.

¿Para qué sirve el límite por IP?

Para frenar el password spraying: más de 10 fallos en 15 minutos desde una IP → 429.

¿Por qué un mensaje único?

Para no revelar si el usuario existe (enumeración de usuarios).

¿Para qué el hash falso?

Para que el login tarde lo mismo exista o no el usuario.

¿Por qué el contador va en un solo UPDATE?

Para que dos intentos simultáneos no lean el mismo valor y se pierda un fallo.

¿Por qué se reinicia el contador al acertar?

Para no bloquear a un usuario legítimo por errores viejos.

¿Qué significan 401, 405 y 429?

No autorizado; método no permitido; demasiadas peticiones.

¿Qué contras tiene el bloqueo?

Se puede bloquear a otro a propósito, y el límite por IP afecta a todos los que comparten red.

¿Qué pide la consigna para este tema?

Limitar intentos, espera progresiva o bloqueo temporal, y registrar los intentos.
